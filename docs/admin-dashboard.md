# 관리자 대시보드와 비즈니스 로그

로그인 후 상단 **관리자** 메뉴를 사용한다. `ADMIN_EMAILS`에 등록한 Google 검증 이메일만 서버에서 허용한다. 환경 변수는 쉼표로 구분하며 기본값은 비어 있어 누구에게도 관리자 권한을 주지 않는다. 역할은 매 요청 확인하고 사용자 입력이나 브라우저의 `isAdmin` 값을 신뢰하지 않는다. 운영 계정 지정은 Terraform의 `admin_emails`로 관리한다.

## 지표 정의

| 지표 | 정의 |
| --- | --- |
| 누적 접속자 | 방문 수집 시작 이후 로그인한 고유 계정 수. 여러 기기·탭은 하나로 집계 |
| 일일 접속자 | KST 오늘 00:00부터 현재까지 고유 계정 |
| 주간 접속자 | KST 이번 주 월요일 00:00부터 현재까지 고유 계정 |
| 월간 접속자 | KST 이번 달 1일 00:00부터 현재까지 고유 계정 |
| 기간 접속자 | 선택한 시작일~종료일을 포함하는 범위의 고유 계정 |
| 전체 사용자 | 현재 등록된 계정 수. 방문 여부와 구분 |
| 신규 사용자 | 선택 기간에 가입한 계정 수 |
| 비용 | 가져온 청구 자료의 크레딧 반영 후 금액. KRW/USD 별도 표시 |
| 매출 | 실제 결제액−환불액. PG 미연동 상태에서는 실제 신규 매출 없음 |
| 미처리 문의 | 접수/처리 중 상태의 전체 문의 |

방문 집계에는 관리자도 포함한다. 로그아웃 상태 방문, 봇의 로그인 화면 요청, 단순 API 호출 수는 접속자에 포함하지 않는다. Google 로그인, 세션 복원 시 방문을 기록한다. 화면이 열린 동안 KST 날짜 변경과 탭 복귀를 확인하여 새 날짜만 전송한다. 서버는 `(user_id, day)` 기본키로 중복을 제거한다. 일별 접속자를 합산해서 주간·월간을 계산하지 않는다.

최대 366일 범위의 일/주/월 차트와 표를 제공한다. 경계 주/월은 조회 기간에 포함된 날짜만 집계한다. 도입 이전 방문은 복원할 근거가 없으므로 미수집으로 표시한다. 가입일은 기존 users 테이블에서 조회할 수 있다. 누적 카드와 이번 일/주/월 카드는 선택한 기간과 별개이며 화면에 명시한다.

## 비용 연결과 경계

현재 `algostep` 프로젝트에는 BigQuery Billing export 데이터셋이 없다(2026-09-19 읽기 확인). GCP 청구 비용을 자동 수집한다고 표시하지 않는다. 비용 JSON 파일의 미리보기와 적용, 운영 API 수집 경로를 제공한다. `review_api_usage`의 실제 모델별 입력/출력/Thinking 토큰은 직접 조회하지만 토큰을 가격으로 임의 환산하거나 청구 비용과 중복 합산하지 않는다.

`비용·매출 → 비용 자료 가져오기`에서 검토된 청구 자료를 업로드한다. 예제는 필드 설명용이며 `REPLACE_` 값이 남아 있으면 서버가 거절한다. 같은 원본 키는 갱신되고 중복 합산되지 않는다. 파일당 500행/512KB UI 제한, 서버 최대 500행, 지원 통화 KRW/USD. 비용의 음수 조정은 허용하며 미래 사용일은 거절한다. 파일 단위로 트랜잭션을 적용한다.

```json
{"entries":[{"sourceKey":"stable-provider-date-service-currency-key","usageDate":"2026-09-19","service":"Compute Engine","currency":"KRW","amount":1234.5,"source":"verified billing export"}]}
```

위 금액은 **문서 예시**이며 운영 데이터가 아니다. 실제 날짜·서비스·통화별 원본 키를 유지한다. 크레딧을 반영한 순비용을 넣고, 이미 포함한 Gemini 비용을 별도로 중복 등록하지 않는다. 금액 0은 확인된 무료/크레딧 적용 비용에만 사용한다. 누락된 행은 0원으로 해석하지 않으며 이 화면은 전체 청구서의 완결성을 보증하지 않는다. 누락·정정은 공급자 자료와 대조하고 동일 키로 교체한다.

자동 수집 작업을 운영할 때는 기존 `docs/billing-actuals.sql`로 Billing export를 조회한 뒤, 제한된 환경에 둔 `OPERATIONS_TOKEN`으로 `POST /api/operations/costs/import`에 동일 형식을 전달한다. 현재 Cloud Run에 추가 BigQuery 권한을 부여하거나 유료 작업/데이터셋을 생성하지 않았다. Billing export 설정과 수집 스케줄 연결은 별도이며 현재는 관리자 파일 가져오기를 사용한다.

PG 공급자와 상품이 미정이므로 결제는 계속 비활성이다. 매출 원장은 지급/환불 이벤트의 고유 공급자 ID를 갖지만 공개/관리자 임의 매출 쓰기 API를 만들지 않았다. 향후 PG 서명 검증과 환불 원거래 연결을 구현한 서버 처리에서만 기록해야 한다. 무료 리뷰 사용은 매출로 기록하지 않는다.

## 문의

로그인한 웹·Android 사용자는 문의하기에서 유형, 제목, 내용을 제출하고 자신의 문의 및 답변만 본다. 24시간 동안 계정당 최대 10건이며 재시도는 requestKey로 중복 생성하지 않는다. 관리자는 페이지/상태별 문의 목록, 사용자 이메일, 답변, 접수→처리 중→완료 상태를 관리한다. 완료 처리에는 답변이 필요하다. revision 충돌은 409로 거절하므로 오래된 탭이 최신 답변을 덮어쓰지 않는다. 답변은 앱 안에서 확인하며 별도 이메일/푸시 전송은 하지 않는다.

## 비즈니스 이벤트

DB 마이그레이션 5에서 `visitor_days`, `business_events`, `support_tickets`, `cost_entries`, `revenue_entries`를 추가한다. 기존 스키마와 기록을 삭제하지 않는다.

회원 가입·로그인·퀴즈 제출·코드 문제 시작·실행 요청/결과·리뷰 요청/성공/실패·학습 기록 삭제·문의 접수/처리·비용 가져오기를 기록한다. 이벤트에는 시각, 유형, 사용자 ID, 엔티티 ID, 사전에 선택한 메타데이터만 포함한다. 코드, LLM 프롬프트, 문의 본문, 비밀번호, 쿠키, API 키는 저장하지 않는다. 엔티티 기반 event_key로 요청 재시도에 따른 중복 집계를 방지하고 상태 변경과 같은 DB 트랜잭션 안에서 기록한다.

기록 삭제/30일 만료 뒤에도 이벤트 집계는 유지한다. 본 기능의 이벤트와 방문 집계는 현재 자동 만료시키지 않으므로 저장량에 따라 보관 정책/집계 아카이브를 추후 정한다. 사용자 탈퇴 기능 도입 시 사용자 ID 삭제·익명화와 누적 지표 보존 정책도 함께 결정해야 한다. 도입 전 이벤트를 소급 생성하지 않는다. 프로세스/네트워크 장애로 API 결과 콜백 자체가 없었던 실행은 완료 이벤트가 없을 수 있으며 운영 큐 상태와 구분한다.

## 검증

관리자 401/403과 CSRF, KST 경계, 고유 사용자 집계, 수집 전 기간, 문의 소유권/재시도/답변 충돌, 비용 통화 분리·중복·원자성·환불 집계, 기록 삭제 후 로그 보존을 통합 검사한다. Playwright로 일반 사용자→관리자→답변 확인, 비용 업로드, 차트·로그 화면, 다크모드와 모바일 너비를 확인한다. 브라우저 비용 데이터는 격리된 테스트 DB에만 입력한다.
